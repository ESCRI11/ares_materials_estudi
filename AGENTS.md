# AGENTS.md

Guide for AI agents working in this repo. Read this before adding or editing anything.

## What this is

A static study site that prepares a **non-technical designer** for the technical
requirements of the MA SUPSI in Interaction Design (2026/27). The reader is smart but
has never used a terminal, git, or an Arduino. Nothing may assume prior programming
knowledge.

Source of truth for scope: `Syllabus-MA-Interaction-Design-2627.pdf` (abridged, 13 pages —
the per-course detail pages it references are missing). It is **gitignored**, so it only
exists on the author's machine; the content map below is what survives in the repo.

## Stack

- **Astro + Starlight**, deployed to **GitHub Pages** via the official Astro Actions workflow.
- Content is Markdown/MDX. Interactivity is opt-in islands — pages ship zero JS otherwise.
- **No backend, no accounts, no database.** Exercise progress lives in `localStorage` or nowhere.

Chosen because adding a lesson is "add a `.md` file" and adding an exercise is "import a
component". Do not migrate off it without being asked.

## Layout

```
src/content/docs/     # every .md/.mdx here becomes a page
src/components/       # Quiz.astro, P5Embed.astro, and nothing else unless justified
src/styles/custom.css # theme overrides — CSS variables, not a Starlight fork
astro.config.mjs      # site + base + fonts + sidebar order + the checklist script
.github/workflows/    # deploy.yml — build and publish on push to main
public/               # images, diagrams
```

`src/content/docs/start-here/how-to-use-this-site.mdx` is the reference page — it uses a
quiz and a checklist. Copy its shape rather than inventing a new one.

## Adding a lesson

1. Create `src/content/docs/<section>/<topic>.mdx` (use `.mdx`, not `.md`, if it has a quiz).
2. Frontmatter needs `title` and `description`. Add `sidebar: { order: N }` to place it
   within its section — without it, ordering is alphabetical and therefore wrong.
3. End every lesson with an evaluation section (see below).

No index to update, no route to register.

**Adding a whole new section** is the one thing that touches config: create the folder and
add one line to `sidebar` in `astro.config.mjs`. That list is in *learning order*, which is
why it isn't autogenerated from the filesystem.

## Exercises (the "evaluation" sections)

Three formats, in order of preference:

- **`<Quiz>`** — `import Quiz from '@components/Quiz.astro'` (the `@components` alias works
  at any folder depth). Pass `questions={[{ q, options, answer, explanation }]}` where
  `answer` is the index of the correct option. `explanation` is required — a wrong answer
  must teach. Marks right/wrong on click, reveals the correct option, scores at the end.
- **Self-check task list** — plain markdown checkboxes (`- [ ] …`) for things a quiz can't
  test ("install this", "push your first commit"). Use for git, terminal, Figma, CAD.
  Markdown renders these disabled, so a script in `astro.config.mjs` re-enables them and
  persists ticks to `localStorage` per page. Nothing to import.
- **`<P5Embed>`** — `import P5Embed from '@components/P5Embed.astro'`, then
  `<P5Embed src="https://editor.p5js.org/<user>/embed/<sketchId>" title="…" />`. Get that
  URL from the p5.js editor's share dialog. It's the editor they'll use in class, and it
  costs us nothing to maintain.

**Do not build an in-page code sandbox** (CodeMirror + live preview). It was considered and
deliberately deferred. Revisit only if the p5 embed proves inadequate.

## Writing rules

- English only. Match the vocabulary the courses use — students will hear these words in class.
- Define every term on first use, including the ones that feel obvious ("repository", "commit",
  "library", "IDE"). The reader has a design bachelor's, not a CS one.
- Short lessons. One concept per page, 5–10 minutes to read.
- Every technical claim the reader must act on gets a copy-pasteable command or a screenshot.
- Prefer showing the smallest thing that works over the complete API surface.

## Deploy

Push to `main` → `.github/workflows/deploy.yml` builds and publishes to
https://escri11.github.io/ares_materials_estudi. Project-page deploy, so `astro.config.mjs`
must keep both `site` and `base` set — dropping `base` silently breaks every asset URL in
production while working fine locally. Internal links written by hand (hero actions in
`index.mdx`, for instance) need the `/ares_materials_estudi` prefix; links inside markdown
prose get it automatically.

Run `npm run build` before committing. It catches broken links, bad frontmatter, and
malformed component props.

## Don'ts

- No new dependencies for something a few lines of CSS or vanilla JS can do.
- No component with one usage — inline it.
- No speculative structure. Add the section when the content for it exists.
- Don't delete or rewrite the syllabus PDF.
