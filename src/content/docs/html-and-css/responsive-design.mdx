Every layout you have made until now started with a canvas: A4, 1920×1080, a Figma frame at
some agreed size. A web page has no such thing. It is drawn into whatever window the reader
happens to have open — a phone held in one hand, a laptop, a projector, a browser dragged to
a third of the screen while something else plays beside it.

**Responsive design** is building one page that works across that whole range, instead of
designing for a width and hoping. The course names it explicitly, and it is the part of CSS
that most changes how you think about a layout.

The mental shift: you are not placing things at coordinates. You are describing relationships
— this column is at most 40 characters wide, this row wraps when it runs out of room, this
image never exceeds its container — and letting the browser resolve them at whatever size it
finds itself.

## The viewport meta tag

Start here, because without it nothing else works on a phone.

The **viewport** is the visible area of the page inside the browser window. Mobile browsers
have an old habit: unless told otherwise, they pretend to be about 980 pixels wide, render a
desktop layout at that size, then shrink the whole thing down. The result is a readable-ish
miniature that you have to pinch to use — and your media queries never fire, because the page
believes it is on a wide screen.

One line in the `head` of the document turns that off:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

It says: treat the viewport as the real width of this device, and start at 100% zoom. Put it
in every page you make. This is the single most common reason a site "works on desktop but is
broken on mobile".

## Relative units

Fixed pixel widths are what break at other sizes. CSS has units that describe a relationship
instead of a measurement.

| Unit | Relative to | Use it for |
|---|---|---|
| `%` | the parent element's size | widths inside a container |
| `rem` | the root font size, normally 16px | almost everything: type, padding, gaps |
| `em` | the current element's font size | spacing that should scale with its own text |
| `ch` | the width of one character | line length, where `60ch` is a good measure |
| `vw` / `vh` | 1% of viewport width / height | full-bleed sections, hero heights |

`rem` deserves the most attention. One `rem` equals the browser's base font size — 16px unless
the reader has changed it, and some readers have, for reasons you should respect. Build your
whole spacing scale in `rem` (`0.5rem`, `1rem`, `1.5rem`, `2rem`) and the entire page scales
with someone's accessibility setting instead of ignoring it.

The other habit worth forming now: **`max-width` instead of `width`**.

The result panel below is narrower than 1200 pixels, which is the whole demonstration: the
first box demands 1200 and runs off the edge, and the second takes what it can get.

<LiveCode
	title="width versus max-width"
	height={320}
	code={`<style>
  body { font-family: Helvetica, Arial, sans-serif; margin: 1rem; }
  div { background: #eee; padding: 1rem; margin-bottom: 10px; }
  .rigid { width: 1200px; }
  .fluid { max-width: 1200px; }
</style>

<div class="rigid">width: 1200px — I am 1200px wide whatever happens, so my right-hand edge is
somewhere off the side of this panel and you have to scroll to reach it.</div>
<div class="fluid">max-width: 1200px — I would take 1200px if there were room. There is not,
so I fit.</div>`}
/>

Change both numbers to `200px` and press Run: now there *is* room for 200 pixels, and the two
boxes come out identical. A fixed width is only a problem when the space is smaller than the
number — which, across every screen your page will meet, is most of the time.

`max-width: 600px` reads as "600 pixels, or the space available, whichever is smaller". Almost
every fixed width in a layout wants to be a max-width. The same applies to images, where
`max-width: 100%` stops a large photo from pushing the page sideways:

```css
img {
  max-width: 100%;
  height: auto;
}
```

For text, cap the measure in `ch` rather than pixels: `max-width: 65ch` gives roughly 65
characters per line at any type size, which is the same judgement you would make setting body
copy anywhere else.

## Media queries

Relative units and wrapping handle a surprising amount on their own. When you genuinely need a
different arrangement — a sidebar that becomes a stacked block, three columns that become one
— you use a **media query**: a block of CSS that only applies when a condition about the
screen is true.

```css
.layout {
  display: flex;
  flex-direction: column;
}

@media (min-width: 40rem) {
  .layout {
    flex-direction: row;
  }
}
```

Read it as: lay this out in a column always; from 40rem (640px) upwards, use a row instead.
The width at which the rule kicks in is a **breakpoint**.

<LiveCode
	title="A layout that changes shape"
	height={380}
	code={`<style>
  body { font-family: Helvetica, Arial, sans-serif; margin: 1rem; }
  * { box-sizing: border-box; }
  .layout { display: flex; flex-direction: column; gap: 1rem; }
  .main { background: #f4f4f4; padding: 1rem; }
  .side { background: #1b1b1b; color: white; padding: 1rem; }

  @media (min-width: 34rem) {
    .layout { flex-direction: row; }
    .side { width: 30%; }
  }
</style>

<div class="layout">
  <div class="main">Main column. Narrow your browser window and watch the sidebar move
  underneath this block.</div>
  <div class="side">Sidebar</div>
</div>`}
/>

Narrow the browser window until this result panel drops below 34rem and the layout switches.
If your window will not go that narrow, change `34rem` to a larger number and press Run — the
breakpoint is a number you choose, not one handed to you.

## Mobile first

Notice the order in that example: the narrow layout is written as the plain rule, and the wide
one arrives inside `min-width`. That is **mobile-first**, and it is the convention.

It is not fashion. Writing the simplest arrangement — one column, everything stacked — as the
base means the fallback is always sound, and each media query adds complexity as space allows.
The reverse (`max-width` queries stripping a desktop layout back) means every small screen
depends on you having remembered to undo everything, and something always survives.

Choose breakpoints where **your** layout stops looking right, not from a list of device sizes.
Drag the window slowly, watch for the width where the line length gets uncomfortable or the
cards get too thin, and put the breakpoint there. Device dimensions change every year; your
content does not.

## What you already have

Two things from the previous lessons were doing responsive work before the term appeared:

- `flex-wrap: wrap` with a `min-width` on the items reflows a row into several rows with no
  media query at all.
- `max-width` with `margin: 0 auto` gives you a centred column that shrinks on its own.

Between them and one or two breakpoints, most pages are done. Reach for a media query when
the arrangement must genuinely change, not for every adjustment.
