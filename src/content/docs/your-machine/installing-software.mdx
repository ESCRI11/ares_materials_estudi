You know one way to install software: find the website, download the installer, drag it to
Applications or click Next four times. It works. For the tools this master needs, it stops
working, for four reasons.

- **You have to find the right website.** Search for a developer tool and the top results
  are often mirrors, ad-funded download portals and outright fakes. This is a genuine and
  common route for malware.
- **Nothing tells you when it is out of date.** Twenty tools mean twenty update habits you
  will not keep.
- **Many of these tools have no installer.** They are not applications with a window; they
  are commands, and there is nothing to drag anywhere.
- **You cannot write it down.** "Download these six things" is not something you can send a
  classmate, or run again on a new laptop, or paste into a lesson.

## What a package manager is

A **package manager** is a program that installs other programs. It holds a catalogue,
knows which version fits your machine, downloads it, puts it where it belongs, and can
update or remove everything it installed with one command.

A **package** is one piece of software plus the information about it: its name, its
version, and its **dependencies** — the other packages it needs in order to run. The
package manager reads that list and installs those too, which is the part that used to eat
whole evenings.

You have already used one: the App Store is a package manager with pictures. Homebrew and
apt are the same idea, driven by text, with a catalogue aimed at people who build things.

The payoff is that installing becomes one line you can copy, and this site can hand you
that line instead of a paragraph of clicking.

## Windows: apt, inside WSL2

Ubuntu comes with its package manager already installed. It is called **apt**, and you use
it from the Ubuntu terminal you set up in the
[WSL2 lesson](/ares_materials_estudi/your-machine/wsl2/) — not from PowerShell.

Run this first, before anything else, on a fresh install:

```sh
sudo apt update
```

`sudo` because it changes something the whole system shares, so it will ask for your Linux
password and show nothing as you type it.

:::caution[update does not update anything]
This is the single most confusing name in Linux. `apt update` downloads a fresh copy of the
**catalogue** — the list of what exists and at which version. It installs nothing and
changes none of your software.

The command that actually installs newer versions is `apt upgrade`. Run `update` first,
always, because `upgrade` can only fetch what the catalogue knows about. A stale catalogue
is why an install sometimes answers "unable to locate package" for something that plainly
exists.
:::

The four commands you will actually use:

```sh
apt search node             # is it in the catalogue, and what is it called
sudo apt install git        # install something
sudo apt upgrade            # install newer versions of everything you have
sudo apt remove git         # take it away again
```

Searching needs no `sudo`, because looking at a catalogue changes nothing. Installing does.

:::note[winget, and when you still want it]
Windows has its own package manager, **winget**, run from PowerShell. It installs Windows
applications — the ones with a window: a browser, Figma, VS Code itself.

That is the division worth keeping in your head. Command-line tools go in with `apt`,
inside Ubuntu, because that is where you will type their names. Windows applications go in
with winget or from their own website, because they are Windows programs and Ubuntu has no
screen to put them on.
:::

## macOS: Homebrew

Homebrew is not preinstalled. Get the install command from its own homepage,
[brew.sh](https://brew.sh) — the whole command sits in a box at the top of the page. At the
time of writing it is:

```sh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Copy it from the site rather than from here, so you get whatever is current. Then paste it
into a terminal and press Enter. Three things will happen, and all three are normal:

1. It asks for your password. Nothing appears as you type it — see the terminal lesson.
2. It may install Apple's Command Line Tools first. That is a large download and can take
   ten minutes or more. Let it finish.
3. When it is done it prints a short **Next steps** section with one or two commands to
   run. **Run them.** They add Homebrew to your `PATH`.

:::note[What PATH is]
`PATH` is the list of folders your shell searches when you type a command name. If a
program is not in one of those folders, the shell answers "command not found" even though
the program is sitting on your disk. Installers that print instructions at the end are
almost always asking you to add themselves to `PATH`.
:::

Check that it worked:

```sh
brew --version
```

A version number means you are set. "command not found" means the Next steps commands were
skipped, or that this terminal window was open before they ran — close it and open a new
one.

The four commands you will actually use:

```sh
brew search node        # is it in the catalogue, and what is it called
brew install git        # install a command-line tool
brew install --cask figma   # install an application with a window (a "cask")
brew upgrade            # update everything Homebrew installed
```

## Practice: install git

Time to install something real. **Git** is the tool that records versions of your work and
is how every course will expect you to hand things in; a whole section of this site is
about it. Right now you only need it on your machine.

On Windows, in the Ubuntu terminal:

```sh
sudo apt update
sudo apt install git
```

On macOS:

```sh
brew install git
```

If apt answers that git *is already the newest version*, it was preinstalled and you have
lost nothing — the command is safe to run either way.

Then check:

```sh
git --version
```

You should see something like `git version 2.45.0` — the exact number does not matter.

:::caution[If it says command not found]
Open a **new** terminal window and try again. A shell reads `PATH` when it starts, so a
window that was already open does not know about anything installed since. This will catch
you at least twice more in your life; the fix is always the same.
:::

## One rule about install commands

Only paste an install command that came from the tool's own documentation or from a lesson
here. Installing software is exactly the moment when a command has power over your machine,
and a plausible-looking one-liner from a forum post or a chatbot is the easiest thing in
the world to get wrong.
