A terminal is always standing somewhere. There is one folder it considers "here", and
every command you type acts on that folder unless you say otherwise. That folder is the
**working directory**, and this lesson is entirely about seeing it, listing it, and
changing it.

Three commands do the job. You will use them every day for the rest of the master.

Everything on this page is typed into zsh on macOS or into Ubuntu on Windows, and it is
identical in both. That sameness is exactly what
[installing WSL2](/ares_materials_estudi/your-machine/wsl2/) bought you.

## Where am I

```sh
pwd
```

Short for *print working directory*. It answers with an absolute path — the full address
of the folder you are in.

When a tool says it cannot find a file that you can clearly see, `pwd` is the first thing
to type. Nine times out of ten you are standing in the wrong place.

## What is in here

```sh
ls
```

Lists the files and folders in the working directory, as bare names in columns. Two
variants earn their keep:

```sh
ls -l      # one per line, with size and date
ls -a      # include hidden files
```

Those are **flags**, from the terminal lesson: a dash and a letter that change how the
command behaves. They combine, so `ls -la` does both.

**Hidden files** are ones whose name starts with a dot. They are not secret; the convention
exists to keep configuration out of your way, and they are invisible until you ask. Two of
them are waiting in the git section: `.git`, the folder holding a project's history, and
[`.gitignore`](/ares_materials_estudi/git-and-github/what-not-to-commit/), the file listing
what git must leave alone.

## Going somewhere else

```sh
cd Documents
```

Short for *change directory*. Afterwards, `pwd` will show you one level deeper. The
important moves:

```sh
cd Documents      # go into a folder that is here
cd ..             # go up one level, to the parent folder
cd ../..          # up two levels
cd ~              # go home, from anywhere
cd ~/Desktop      # straight to an absolute location, from anywhere
```

Everything after `#` in those lines is a comment for you, not part of the command — leave
it out when you type.

A fresh Linux home starts empty, so on Windows that last one answers *No such file or
directory* until you have made a Desktop folder. That is the shell being precise rather
than broken, and it is the same message you get for a typo.

The argument to `cd` is a path, exactly as described in the paths lesson: relative if it
starts with a folder name or with `..`, absolute if it starts with `/` or `~`. This is the
moment that lesson pays for itself.

:::note[Windows readers: getting to your Windows files]
Inside Ubuntu your `~` is the Linux home directory, which starts out empty. Your Windows
drives are one folder away, under `/mnt/c`:

```sh
cd /mnt/c/Users/ares/Downloads
```

Use that to reach something that already lives on the Windows side — a photo, a PDF, a
Figma export. Keep the work you make in `~`, for the speed reason in the
[WSL2 lesson](/ares_materials_estudi/your-machine/wsl2/).
:::

## Tab completion, the habit that matters most

Type the first two or three letters of a name and press **Tab**. The shell finishes it for
you.

```sh
cd Doc      # press Tab here
```

becomes `cd Documents/` on its own. This is not only about typing speed:

- If Tab completes the name, that folder **definitely exists**, spelled that way.
- If nothing happens, what you typed matches nothing — or matches several things, and
  pressing Tab a second time lists them.
- Names with spaces get escaped or quoted correctly, which is fiddly to do by hand.

Learn to press Tab reflexively after every few characters. People who look fluent in a
terminal are mostly people who never type a full filename.

If you do need to type a name with a space in it yourself, wrap it in quotes — this works
on both systems:

```sh
cd "Design Research"
```

## Two shortcuts worth stealing

**Drag a folder into the terminal window** and its full path is pasted at the cursor. Handy
when the folder is somewhere deep and you have it open in a window anyway. On Windows this
pastes the path in its Windows form, `C:\Users\ares\Desktop`, which bash does not
understand — swap the leading `C:\` for `/mnt/c/` and the backslashes for forward slashes,
and it works.

**Up arrow** to bring back the last command, then edit it, rather than retyping.

## Making a folder

```sh
mkdir ind-prep
```

*Make directory*. Do this in your home folder now — it is where everything from these
lessons will live. On Windows that means the Linux home, the one `cd ~` takes you to, not
anywhere under `/mnt/c`.

```sh
cd ~
mkdir ind-prep
cd ind-prep
pwd
```

Four lines, and you have created a project folder and walked into it. That last `pwd`
should print something ending in `ind-prep`.

:::caution[Treat capital letters as different letters]
A Mac will usually let `Ind-Prep` and `ind-prep` refer to the same folder. Linux — which
is what you are typing into inside WSL2 — will not, and neither will GitHub or any server
your work ends up on. A project that works on a laptop and breaks after upload is very
often one capital letter. Use lowercase and stop thinking about it.
:::
