**Visual Studio Code** — everyone says *VS Code* — is a **code editor**: an application for
writing and editing plain text. It is named explicitly in the Creative Coding Foundations
course, it is free, and it behaves the same on macOS and Windows.

**Plain text** means characters and nothing else — no fonts, no bold, no page size. Code
has to be plain text, which is why a word processor is the wrong tool: Word and Pages
quietly replace your straight quotes with curly ones and your hyphens with dashes, and code
written with curly quotes does not run. A code editor never touches what you typed.

This lesson installs it and gets you comfortable with the window. No code yet.

## Install it

Download from [code.visualstudio.com](https://code.visualstudio.com) — the site detects
your system and offers the right build. On macOS you get a `.zip`; unzip it and drag
*Visual Studio Code* into your Applications folder, which is the step people forget.

Or, now that you have a package manager, do it in one line:

```sh
brew install --cask visual-studio-code
```

```powershell
winget install --id Microsoft.VisualStudioCode -e
```

:::caution[Windows: install it into Windows, not into Ubuntu]
VS Code is an application with a window, so it belongs on the Windows side — the download
page or that winget line in PowerShell, not `apt` inside Ubuntu. The next section connects
it to your Linux files, which is how you get an editor that looks like Windows and works on
Linux at the same time.
:::

Open it. You get a Welcome tab and possibly a colour theme picker; pick whichever you like
and ignore the rest of that tab.

## Windows: connect it to WSL2

Your project files live in the Linux home directory, and VS Code is a Windows program.
Bridging that is one extension and one command, and it is the difference between an editor
that fights you and one you stop thinking about.

An **extension** is an add-on that teaches the editor something new. Open the Extensions
panel (Ctrl+Shift+X), search for **WSL**, and install the one published by Microsoft. It is
free and it is the only extension this section asks for.

Now open your project. From the Ubuntu terminal:

```sh
cd ~/ind-prep
code .
```

Remember that `.` means "the folder I am in right now". The first time you run `code`, it
spends a moment installing a small helper inside Ubuntu; after that it is instant. A VS
Code window opens on your `ind-prep` folder.

The same thing without the terminal: open the command palette with Ctrl+Shift+P, type
`WSL`, and choose **WSL: Connect to WSL**. Then File → Open Folder, which now browses the
Linux filesystem rather than `C:`.

**How to tell it worked.** Look at the far bottom-left corner of the window. There is a
small coloured block, and once you are connected it reads **WSL: Ubuntu**. If it is empty,
you are editing Windows files and the commands in later lessons will not behave.

Two things follow from being connected, and both are the point of the exercise:

- The **integrated terminal** inside VS Code is now bash inside Ubuntu, standing in your
  project folder. Everything from the moving-around lesson works in it as written.
- Extensions split into two groups. Some run on the Windows side, where the window is;
  others have to run next to your files, and for those VS Code shows a button reading
  **Install in WSL: Ubuntu**. Click it when you see it. Nothing is broken — it is the
  editor telling you which side of the machine an add-on belongs on.

:::note[The slow way, and why not to use it]
You can also open `\\wsl$\Ubuntu\home\you\ind-prep` — or `\\wsl.localhost\Ubuntu\...`, the
newer spelling of the same address — in a plain VS Code window. It works,
and it is the wrong habit: the editor is then reaching across the filesystem boundary for
every read and every save, its terminal is PowerShell rather than bash, and git gets
noticeably slow. Connect properly once and forget about it.
:::

## Open a folder, not a file

This is the one habit to take from this lesson.

VS Code is built around an open **folder**, which it calls your workspace or project.
Almost everything useful is scoped to that folder: the file tree, search across every file,
the built-in terminal, and later on git. Open a single file instead and you have an
expensive notepad.

Use **File → Open Folder** and choose the `ind-prep` folder you made in the moving-around
lesson.

You may see a dialog asking whether you **trust the authors of the files in this folder**.
It is a real safety feature — code in a folder can run when you open it. For folders you
created yourself, choose the trusting option. For a folder downloaded from a stranger,
do not.

## The four things you need

Down the left edge is a strip of icons. Four of them matter now.

**Explorer** — the top icon, or Cmd+Shift+E on macOS, Ctrl+Shift+E on Windows. This is the
file tree of the open folder. Hovering over the folder name gives you icons for *new file*
and *new folder*. When you create a file here you type its whole name including the
extension: `index.html`, not `index`.

**Search** — Cmd+Shift+F or Ctrl+Shift+F. Searches every file in the folder at once. The
day you cannot remember where you wrote something, this is the answer.

**Extensions** — Cmd+Shift+X or Ctrl+Shift+X. Add-ons that teach the editor something new:
a language, a formatter, a preview pane. Resist installing a pile of them today. Each
section of this site names the ones it actually needs — on Windows that list starts and,
for now, ends with WSL — and an editor full of unexplained extensions is harder to learn
in, not easier.

**The integrated terminal** — View → Terminal, or Ctrl and the backtick key (the one above
Tab, to the left of the 1). A terminal opens in the bottom half of the window, and here is
the payoff: it starts **already inside the folder you have open**, and on Windows it is the
Ubuntu shell rather than PowerShell. Try it:

```sh
pwd
```

It prints the path to `ind-prep` without you having typed a single `cd`. From now on this
is where you will run commands, with your files visible above them.

## The command palette

Press Cmd+Shift+P on macOS or Ctrl+Shift+P on Windows and a text box drops from the top.
Every command in VS Code is in there, searchable by name — faster than reading menus, and
the way documentation will tell you to do things.

Two worth knowing now:

- Type `terminal` to find *View: Toggle Terminal*.
- Type `WSL` to find *WSL: Connect to WSL*, on Windows.
- On macOS only, type `shell command` and run **Shell Command: Install 'code' command in
  PATH**. That lets you type `code .` in any terminal to open the current folder in the
  editor. On Windows the WSL extension puts `code` into your Ubuntu shell for you the first
  time you use it.

## One setting to change

**File → Auto Save.** Tick it. Otherwise you will eventually spend twenty minutes debugging
a file you forgot to save, which is a rite of passage worth skipping.
